Evidence reviewed on 31 October 2026, Asia/Tashkent. This audit reuses the six retained YouTube captures in `output/acts-rea-evidence.json`; it does not claim a new visit to ACTS or a complete video review. Selected screenshot pixels were inspected again, and chapter descriptions were decoded from the captured YouTube DOM. YouTube accessibility text identifies page controls; it does not expose controls drawn inside video frames.

## What the retained evidence establishes

ACTS presents a three-stage working sequence: **Data Input → Load Distributor → Plotting Board**, preceded by school settings. Its load-distribution workspace is an important part of the manager's job, not simply a list of already-created lessons. Additional WIST review stages are reconstruction choices, not observed ACTS approval gates.

## Five immediate UI priorities

1. **A manager starting point and progress strip.** Show the school week, supplied people/rooms, Model 1 options, teaching loads, constraints, input validation and plotting. Each stage needs a concrete action and next step, rather than a decorative percentage.
2. **A load-assignment workbench.** Keep teacher capacity feedback beside the lesson/section requirement being assigned. Allow a manager to preview teacher and room changes for a filtered set of existing activities, then commit them together. Never silently merge pupils or claim team teaching when the intention is replacement.
3. **Editable planning staff and useful resource setup.** Add/edit timetable-only staff attributes and room capacity/availability, showing the connection to curriculum eligibility and load. Keep these changes separate from live MIS accounts and pupil records.
4. **Readiness that reflects actual data.** Flag absent teachers/rooms, broken option memberships, impossible demand and bad time grids before generation. Track reviewed input signatures; editing an input should reopen dependent reviews. Existing placement gaps should keep the finished timetable incomplete without being misreported as malformed input.
5. **A visible route from validation to refinement.** Generation should state what changed, preserve fixed work, leave unassigned lessons explicit and link them to Find slots. Provide backups and a route back to load assignment when staff/resources—not placement order—need correction.

## Boundaries and open questions

- The exact ACTS import schema, validation gates, persistence model, expertise-ranking algorithm and automatic load-assignment behavior remain unknown.
- The publisher's descriptions include performance/accuracy claims. These are not proof that all data sets solve, and are not WIST guarantees.
- The manager's review checklist and dependency invalidation are WIST design choices inferred from the observed workflow; they were not observed as mandatory ACTS gates.
- User constraints control the reconstruction: Model 1 only; four lessons per chosen option subject; PE doubles; no free teaching periods through Year 11; fictional test choices; preparation for 2026–27 changes.
- New ACTS capture was unnecessary for this bounded audit: the retained evidence answered the stage-order and load-workbench questions. Additional runtime study would be needed before claiming parity for import, deep search, ripple moves or substitutions.
