# Classroom portfolios and discussions — 0.22.0

Students open **Classroom → Portfolio** to collect evidence, reflections, tags and snapshots of their own returned work. Drafts autosave privately. **Submit for review** makes an entry visible to its allocated teacher. Teachers can approve it, return it with feedback, and explicitly allow linked family accounts to view it. Editing approved work revokes approval and family sharing. Archive is reversible. Student quiz answers, prompts and marking keys are not copied into portfolios.

Teachers open a class’s **Discussions** tab to create a prompt and optionally attach files. Student replies require approval by default. Teachers can close replies, pin topics, return responses with private feedback, and require an approved first response before students can read classmates’ ideas. Students can save private reply drafts. Topic and reply revisions protect against stale saves and reviews.

Parents open **Family portal → Portfolio**. Every request checks the current Directory relationship; only approved, explicitly shared, non-archived entries are visible. Portfolios and discussions never transfer marks into the MIS.

Verification: 247 automated tests and syntax checks pass. Browser QA covered student autosave and evidence upload, returned-work selection, submission, teacher approval, family viewing, student discussion posting and teacher moderation. Existing browser data is retained in the same integrated-demo database.

Public hosting remains the free browser-local demonstration. Records do not sync between colleagues or devices. These controls model the intended workflow; public demo accounts and local storage are not production authentication or storage.
