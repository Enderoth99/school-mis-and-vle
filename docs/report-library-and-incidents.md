# Reports library and class-filtered incidents — 31 October 2026

The incident form now requires Year, Class / form, then Student. Class options contain only forms represented in the signed-in teacher's allocations; pupil options are restricted to the selected year and form. Changing either parent selection clears the child selection. Save validation repeats this membership check, so stale or altered student values cannot slip through. Administrative accounts can select the whole-school population. Existing incident IDs and student IDs are retained; new incidents also store year and group context. Incident records remain browser-local, as in the existing demo.

The reporting library transcribes the user's Reporting.pdf, found at Downloads/TT/Reporting.pdf after the upload: Attendance (1), Class Attendance (7), Gradebook (17), Other (1), Report Cards (3), Schedule (1), School Attendance (3), Standards & Proficiencies (1), Student Information (14), User Information (1). All 49 source titles and format labels are retained. Descriptions are concise paraphrases.

The UI provides favourites, search, category filtering, collapsible card groups, preview filters, recent exports and CSV downloads. Printable WIST-branded views use the browser's Print / Save as PDF facility, including label and envelope layouts. Original catalogue title suffixes such as Excel or Zip describe the source list; this release actually offers CSV and printable views, not native XLSX or ZIP output. Source categories without configured standards/proficiency records show an explicit unconfigured message rather than deriving standards from assessment percentages.

The `/api/reporting/run` endpoint validates the session and origin and applies teacher ownership before reading data. It gathers saved attendance, assessments, Directory contacts, report comments, issued reports and actual sign-in records. Local saved lesson plans and assignments are supplied by the client but filtered against the same server-side class scope. Registration reports do not infer presence when no registration is saved. Final-grade outputs distinguish calculated assessment means, reported attainment and actually issued attainment; semester/exam weighting remains unconfigured. Teacher login reports show only that account; administrators see staff accounts. CSV output uses the existing formula-safe exporter.

Browser QA exposed quota pressure caused by thousands of untouched legacy report placeholders in the local workspace. New integrated workspaces no longer generate those placeholders. On load, only the exact untouched sample patterns are omitted; timestamped teacher entries and other imported content remain, and the separate authoritative report store is not modified. Regression tests cover preservation. Administrative preference and incident saves preserve other teachers' records and prohibit arbitrary teaching-record edits.
